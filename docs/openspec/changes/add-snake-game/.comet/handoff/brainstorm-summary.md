## 已确认事实（来自 Open 阶段，不再重议）

- 交付物：仓库根目录下 `index.html`、`style.css`、`game.js` 三个文件，无构建步骤、无第三方依赖，双击即玩
- 输入：仅键盘，方向键 + WASD 双套映射
- 玩法：基础版（移动、进食增长、计分、撞墙/撞身结束、重开）
- 非目标：触屏与移动端、最高分持久化、逐级加速、暂停/继续、穿墙模式
- 行为契约：`specs/snake-game/spec.md`（确认后为 7 条 Requirement / 17 个 Scenario）

## 关键约束

- `file://` 协议下 ES module 会被 CORS 拦截 → 必须用单 IIFE 组织，不能拆 module
- 项目不引入测试框架（已确认的非目标）→ 验证手段只能是「浏览器中可观察的行为」与「对交付文件的直接检查」
- 初始值：20x20 格、每格 24px（画布 480x480）、节拍 150ms；均为可调常量

## 确认的技术方案

1. 渲染：单个 `<canvas>` + Canvas 2D，每帧重绘
2. 主循环：`requestAnimationFrame` + 时间累加器（规避 `setInterval` 后台节流与漂移）
3. 状态：格子坐标数组（索引 0 为蛇头）+ `{x,y}` 方向向量；像素换算只在绘制阶段
4. 转向输入：长度 1 的待处理方向槽，与**当前实际方向**比较后再应用
5. 食物生成：遍历网格收集空格集合后随机取值；空格集合为空时结束本局
6. 代码组织：`game.js` 内单一 IIFE，按「常量 → 状态 → 输入 → 推进 → 绘制 → 主循环」分区
7. 结束与重开：**画布内覆盖层 + 空格键重开**，不新增 DOM 元素
8. 游戏状态机：`RUNNING | OVER` 两态；重开与首次开局共用同一套初始化函数
9. 画布分辨率：按 `devicePixelRatio` 放大内部分辨率后缩放绘制上下文

## 关键取舍与风险

- [后台标签页切回瞬间补步过多导致连撞] → 单帧补步设上限，超出部分丢弃
- [高 DPI 屏幕下 Canvas 发虚] → 按 `devicePixelRatio` 放大内部再缩放
- [蛇铺满网格时食物无处生成] → 空格集合为空即结束本局（已作为 Spec Patch 固化）
- [状态与渲染耦合导致逻辑无法单独推理] → 逻辑函数只读写格子坐标状态，绘制函数只读状态
- [重开逻辑与首次初始化分叉而产生行为不一致] → 两者共用同一个初始化函数
